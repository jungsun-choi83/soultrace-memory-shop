# 실제 SoulTrace · 주문 · 결제 연결 설계

이 문서는 **추가 구현을 위한 제안 계약**입니다. 아래 URL·데이터 모델은 실제로 존재하는
Eternal Beam/SoulTrace API가 아닙니다. 실제 저장소를 확인해 기존 구조에 맞춰야 합니다.

## 현재 경계

정적 프런트엔드만 제공됩니다. 예시 아카이브는 catalog.mjs에 있고, 주문 결과는 브라우저에서
임시 식별자를 만들어 보여주는 동작입니다. 어떤 서버에도 고객 데이터·결제 요청을 보내지 않습니다.

## 1. 인증 / 아카이브

- 기존 SoulTrace의 로그인 체계·사용자 ID·권한 모델을 재사용합니다. 또 다른 사용자 DB를 임의 생성하지 않습니다.
- 로그인된 사용자 자신이 소유하거나 명시적으로 권한 받은 콘텐츠만 조회합니다.
- 관리 키를 브라우저에 넣거나, URL 파라미터로 토큰·펫 이름·개인 편지를 전달하지 않습니다.
- 서로 다른 서브도메인의 세션 전달은 기존 인증 구조를 확인한 뒤 설계합니다.
- 사진/원본은 비공개 저장소에 저장하고 접근 만료·다운로드·삭제 정책을 구현합니다.
- 현재는 대표 사진 1장입니다. 여러 사진, 이미지 자르기, 실제 인쇄 치수/해상도/여백,
  최종 교정 승인, QR 연결 범위는 제작 계약에 맞춰 별도로 구현합니다.

제안 응답 예시(필드 이름은 실제 API에 맞춰 변경):

```json
{
  "archive_id": "server-generated-id",
  "pet_id": "authorized-pet-id",
  "display_name": "사용자가 등록한 이름",
  "letter_ids": ["owned-letter-id"],
  "photo_ids": ["owned-private-photo-id"]
}
```

## 2. 서버 카탈로그 / 견적

클라이언트는 `product_id`, `variant_id`, `quantity`, 허가된 콘텐츠 ID와 배송 국가 등을 전달하고,
가격·재고·옵션·배송 가능 여부·배송비·세금·합계는 서버가 판단합니다.
해외 정책 미정 국가에는 견적을 발급하지 않습니다. 0원으로 대체하지 않습니다.

```json
{
  "quote_id": "server-quote-id",
  "currency": "KRW",
  "items_subtotal": 84700,
  "shipping": null,
  "tax": null,
  "total": null,
  "expires_at": null,
  "checkout_allowed": false,
  "reason": "SHIPPING_POLICY_NOT_CONFIGURED"
}
```

위 금액은 세 상품 각 1개의 상품 합계 예시이며 총결제금액이 아닙니다.
견적은 사용자·항목·주소 범위·유효기간과 연결하고, 재고/가격/주소 변경 시 다시 검증합니다.

## 3. 주문 / 결제

- 주문 초안은 서버가 생성하고 명시적 사용자·콘텐츠 소유권을 확인합니다.
- 결제 시 클라이언트의 amount를 신뢰하지 않고 저장된 유효 견적과 대조합니다.
- 선택한 PG의 공식 최신 문서를 확인한 후 서버 비밀키와 브라우저 공개키를 분리합니다.
- 결제 콜백 URL에 온 성공 문자열만으로 PAID가 되지 않습니다. 서버 확인이 필요합니다.
- 웹훅은 공급자별 검증 방식을 적용하고 재전송·지연·중복 이벤트를 안전하게 처리합니다.
- idempotency key, 주문 상태 전이, 동시 요청, 중복 제작 지시를 검증합니다.
- 실패·취소·환불·부분 취소의 업무 규칙은 결제/재고/제작 상태와 함께 정의합니다.
- 유료 샌드박스 테스트 없이 demo 플래그만 바꾸어 배포하지 않습니다.

제안 주문 상태:
`DRAFT → AWAITING_PAYMENT → PAID → PROOF_APPROVAL → PRODUCTION → SHIPPED → COMPLETED`
실패·취소·환불은 각 상태와 계약 조건에 따라 허용되는 별도 전이로 정의합니다.

## 4. 개인화 데이터 / 제작사

- 인쇄 요청에서 최소한의 사진·문구와 주문 식별자만 전달합니다.
- 제작사·배송사별 데이터 항목, 처리 국가, 보관/삭제, 계약을 확인합니다.
- 자유서술 편지를 분석 도구·오류 로그·영업 파트너 대시보드에 흘리지 않습니다.
- 사진·문구의 공개 홍보 사용과 이메일 마케팅 동의는 구매/제작 처리와 별개입니다.
- 회원 탈퇴, 개별 콘텐츠 삭제, 주문 법정 보관 기록, 백업 삭제를 분리합니다.
- 배송 확인 뒤 인쇄용 임시 파일의 삭제 주기와 책임자를 정합니다.

## 5. 배포

- `npm run build`의 dist/는 정적 호스팅용입니다. 어떤 서비스에도 현재 배포하지 않았습니다.
- 도메인 후보는 shop.eternalbeam.com이지만 DNS 변경이나 도메인 연결은 수행하지 않았습니다.
- 운영용 HTTPS, CSP, 접근제어, 로그 처리, 캐시 정책은 실제 호스팅 환경에서 설정합니다.
- preview.html은 디자인 전달용입니다. 전체 고객 앱으로 연결할 때는 분리 소스를 사용하는 편이 좋습니다.
- noindex 제거는 실판매 준비 완료 후 별도로 결정합니다. noindex는 개인정보 접근제어가 아닙니다.
