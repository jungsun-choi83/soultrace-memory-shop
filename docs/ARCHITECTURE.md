# v2 구조 / 고객 동선

## 두 개의 동등한 입구

A. `내 편지 불러오기` → 이메일 → 6자리 코드 → 내 편지 목록 → 내용/사진 선택.
B. `사진과 문구 직접 넣기` → 바로 상품 편집. 기존 SoulTrace 이용 이력이나 가입을 강요하지 않음.

상품을 먼저 고른 상태에서 A로 들어가도 색상·수량·작성 중 문구는 보존합니다.
인증/선택을 취소하면 기존 작성 상태로 돌아오고, 선택을 확정하면 해당 상품의 개인화 내용만 바꿉니다.

## 서비스 간 관계

```text
SoulTrace
  설문 → 편지 생성 → 저장된 기록 + 검증된 소유권
                     ↑
             최소권한 서버 간 bridge
                     ↑
Memory Shop Node API
  일회용 이메일 확인 → 30분 세션 → list/read/photo 권한 확인
                     ↑
Memory Shop 브라우저
  선택 기록을 탭 메모리에 보유 → 상품 편집 → 장바구니 → 주문 미리보기
```

쇼핑몰은 이메일함을 읽지 않습니다. 메일 수신자를 새 마케팅 고객으로 자동 등록하지 않습니다.
쇼핑몰 인증 DB는 임시 접근을 위한 것이며, 또 다른 영구 사용자·펫 DB를 만드는 설계가 아닙니다.
이메일 확인 세션을 기존 SoulTrace 로그인/MFA를 우회하는 수단으로 쓰지 않아야 합니다.

## API

| API | 목적 | 인증 |
|---|---|---|
| GET /api/session | 모드, 세션 만료, CSRF 값 | 익명 가능 |
| POST /api/auth/request-code | 이메일로 번호 발송 | 동일 Origin + CSRF + 요청 제한 |
| POST /api/auth/verify-code | 번호 확인, 세션 발급 | 브라우저에 결합된 일회용 challenge |
| POST /api/auth/logout | 서버 세션 폐기 | 동일 Origin + CSRF |
| GET /api/archives | 인증된 소유자의 기록 목록 | 세션 + 원 서비스 권한 |
| GET /api/archives/:id | 선택한 편지 | 세션 + 기록 소유권 |
| GET /api/archives/:id/photos/:photoId | 비공개 사진 | 세션 + 기록 및 사진 소유권 |

발송 요청 시 기존 기록 유무를 조회하지 않습니다. 정상 이메일 형식이면 같은 절차를 따르고,
인증을 마친 뒤에만 목록/빈 상태를 구분합니다. 메일 발송 실패는 성공으로 꾸미지 않습니다.

## 상태

`loading → email → code → list(empty 포함) → detail → product`

오류: 이메일 형식 / 잘못된 번호 / 만료 / 재전송 제한 / 시도 초과 / 세션 만료 /
아카이브 서버 장애 / 권한 없음 / 사진 없음 / 사진 전송 실패.

API 장애 시 예시 결과로 대체하지 않습니다. 잘못된 번호로 성공 화면에 진입하지 않습니다.
사진 다운로드 실패 시 해당 오류를 안내하고 `사진은 나중에 직접 넣기` 선택을 허용합니다.

## 데이터 수명

- 인증 코드: HMAC, 10분, 최대 5회 실패.
- 세션: 원문 토큰은 HttpOnly host-only cookie, 서버는 해시만 보관. 30분 절대 만료.
- 이메일: 서버 SQLite에서 AES-256-GCM 암호문으로 보관. 키는 DB와 분리.
- 요청 제한: 키를 HMAC 처리하며 원문 IP/이메일을 저장하지 않음. 한 시간 단위 기록 등 만료.
- 브라우저 개인화: 메모리 전용. 사진은 재인코딩 미리보기.
- localStorage: 비개인 상품/옵션/수량만.
- 외부 메일·기록 업체의 보관 및 실제 로그는 각각 별도로 확인. 이 코드의 TTL이 외부 보관을 보장하지 않음.
