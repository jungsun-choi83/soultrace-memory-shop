# Cursor 시작 지시문 — SoulTrace Memory Shop v2

아래 내용을 현재 폴더와 **실제 SoulTrace 저장소**를 함께 열어 Cursor에 전달하세요.
실제 저장소가 없으면 테이블·권한·API가 존재한다고 가정하지 말고 연결 필요사항을 보고해야 합니다.

---

기존 SoulTrace Memory Shop v2를 실제 SoulTrace 서비스에 연결하라.

## 변경하지 말 것
- 기존 시각 디자인, 세 상품과 가격(24,900/49,900/59,900원), 직접 입력 구매 경로 유지.
- 별도 비밀번호 가입 화면을 만들지 않는다. 기존 계정이 있으면 재사용하되, 이메일 입력만으로 데이터 조회 금지.
- 마케팅 동의나 AI 학습을 이메일 인증에 강제로 결합하지 않는다.
- 미연동 결제·주문·배송을 성공한 것처럼 표시하지 않는다.
- 임의의 품종/일반 펫 이미지로 이용자의 사진을 대체하지 않는다.
- 아카이브 원본 편지는 사용자가 상품 문구를 편집해도 바꾸지 않는다.

## 1단계: 읽기 전용 조사 후 보고
실제 SoulTrace에서 다음 파일/함수/테이블을 근거로 찾아라.
1. 설문 제출·이메일 입력·편지 생성·이메일 발송 경로.
2. 원본/생성 편지·사진을 DB와 저장소에 보관하는지, URL이 만료되는지.
3. 안정적인 record_id, pet_id, user/owner ID와 이메일 소유권 확인 기록.
4. 기존 미인증 이메일만 적힌 기록과 인증된 기록을 구분할 수 있는지.
5. 실제 Resend 및 DB/Storage 설정. 비밀값은 출력하지 말 것.
없으면 UNKNOWN으로 표시하고 재업로드/별도 소유확인 또는 새 결과 저장이 필요한지 제안하라.

## 2단계: 최소 bridge 구현
`docs/SOULTRACE_BRIDGE.md`의 list/read/photo 계약을 기존 프레임워크에 맞춰 구현하라.
이 문서의 endpoint는 제안 명칭이지 기존 API의 존재 증거가 아니다.
서버 전용 최소권한 키를 검증하고 verifiedEmail을 기존 검증된 subject에 연결한다.
이메일 문자열 일치만으로 모든 과거 기록을 돌려주는 SQL을 만들지 않는다.
미검증/오입력/공유 이메일·위임·계정 MFA 정책과 충돌하는 기록은 자동 허용하지 말고 정책을 검토하라.
list, read, photo 매 요청에 소유권·삭제 상태·접근 권한을 재검증한다.
클라이언트가 전달한 user_id/email/owner_id를 조회 권한으로 신뢰하지 않는다.
원본 답변 전체가 아니라 상품에 필요한 이름·편지·허가된 사진만 반환한다.
프라이빗 사진은 이 패키지 서버의 보호된 경로로 전달하고 공개 URL을 만들지 않는다.

## 3단계: 운영 전 검증
- .env.example에 맞춰 실제 서버에서만 설정. SHOP_MODE=live는 미설정 시 기동 실패 유지.
- 기본 단일 서버 SQLite를 서버리스/다중 인스턴스에 그대로 복사하지 않는다.
- 프록시 접근제어, 요청 제한, HTTPS, 실제 DNS/도메인, API 경로 충돌을 확인한다.
- 프록시 X-Forwarded-For를 무조건 신뢰하지 않는다.
- 이메일 정상 발송·실패·코드 만료·재사용·재전송·시도 초과 확인.
- 다른 이메일의 아카이브 ID, 사진 ID를 넣어도 원문·사진이 유출되지 않는지 확인.
- 미인증 과거 기록 접근 차단, 사진 없는 편지, 저장되지 않은 편지, 서버 장애 테스트.
- 메일 본문·원본 편지·사진 URL·이메일이 광고 이벤트/오류 로그에 유출되지 않는지 확인.
- 개인정보처리방침이 실제 인증/조회/정산 흐름과 일치하는지 운영 담당자에게 확인.
- npm run check 및 실제 통합 테스트를 실행하고 실제 결과만 보고한다.

결과 보고: 변경 파일 / 기존 구조 근거 / 검증 결과 / 실제 연결된 기능 / 미연동 사항.
처음에는 계획·조사 결과를 보여주고, 운영 DB 변경이나 실제 고객 데이터 접근은 별도 승인 없이 수행하지 말라.
